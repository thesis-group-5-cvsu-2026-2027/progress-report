  1. Complete account balance calculation. Connect the ledger to BalanceCalculator and StandingEvaluator; verify against real database records.
  2. Implement reversals properly. Dedicated service that preserves history, reverses matching allocations, and blocks duplicates.
  3. Strengthen accounting tests. Partial payments, over-allocation, reversal behavior, concurrent allocation attempts.
  4. Persist transaction eligibility rules. Keep unconfigured types denied by default.
  5. Build financial workflows. Controllers, validation, and staff UI — only after the accounting rules hold.

Bottom line. The project is no longer just authentication and homeowner records. It now has a migrated financial schema, configurable standing rules, a tested eligibility engine, and an allocation service that enforces real payment limits.

The most valuable next milestone is not adding more tables — it's making account calculation and reversals fully reliable, then connecting them to the UI. That gives us a dependable financial core before the rest of the system grows around it.
